# Phase L15後保守：リファクタリングと初期描画最適化

状態：完了

## 目的

Phase L16へ進む前に、仕様・URL・DB・公開範囲を変えず、断片化したクライアント処理と初期描画負荷を整理する。

## 実装

- 機能別APIクライアントで重複していたJSON成功／失敗処理を共通化する
- タイムラインのReact Query定義を専用Custom Hookへ集約する
- 所有者タイムラインでは、初期表示に必要なプロジェクト、種別、タイムライン項目をServer Componentで取得し、イベント、年代背景、意味的関係をClient Componentから並列取得する
- ルート遷移中と補助データ取得中は、最終レイアウトと同じ領域を確保するスケルトンを表示する
- 管理メニュー配下の非初期UIを操作時に動的ロードする
- 静的解析で参照がないことを確認したUIテーブル部品とブラウザ用Supabaseクライアントを削除する

## 互換性

- 公開タイムラインは検索・共有時の完全な初期HTMLを維持するため、従来どおりサーバーで全表示データを取得する
- API URL、DB、RLS、入力形式、表示機能は変更しない

## DB・容量

- マイグレーション、RLS、制約、インデックス、保存データの変更はない

## 完了条件

- 遅延取得中にレイアウトシフトを生じさせない固定領域のスケルトンが表示される
- 既存の全検証と追加した回帰テストが成功する
