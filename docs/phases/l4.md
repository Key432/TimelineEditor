# Phase L4：変更履歴・ゴミ箱・復元

優先度：P0

状態：完了（保存単位のフィールド差分、GitHub風の行差分、特定版復元、手動チェックポイント、ゴミ箱・復元・明示完全削除、10版／10日／25MB上限、5日後の日次自動削除）

## 目的

完全自動保存、一括編集、内部リンク導入前に、誤操作からデータを復元できるようにする。

## 実装

- アイテム・イベントの差分履歴
- 変更前後の比較
- 特定版への復元
- ゴミ箱
- ゴミ箱からの復元
- 手動チェックポイント
- 履歴保持期限・保持数・容量上限の固定適用（画面表示なし）
- 古い自動履歴の自動整理
- 将来の一括操作を同一トランザクションで履歴化・UndoするためのDB基盤

## 容量最適化

- 全レコードの完全コピーは禁止
- 差分だけを保存
- 明示保存1回を1履歴とし、入力途中の状態を保存しない
- 検索インデックス、統計、レンダリング結果は履歴対象外
- ゴミ箱内データも保持期限を設ける
- 容量超過時は古い自動履歴から削除する
- ゴミ箱は5日保持し、Supabase Cron（`pg_cron`）で日次完全削除する
- 無制限履歴はWindows版限定とする

## 完了条件

- 誤編集・誤削除を期限内に復元できる
- 履歴容量が設定上限を超えて増え続けない
- 全検証成功
