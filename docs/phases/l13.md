# Phase L13：データ品質チェック・重複統合

優先度：P1

## 品質チェック

- 内部リンク切れ
- 削除済み参照
- 親を持たないイベント
- 全親の期間外にあるイベント
- 出典、本文、必須カスタムフィールドの不足
- 不正な外部URL
- 未使用タグ・種別
- 孤立した関係
- Markdown記法上の問題

「公開中だが未完成の項目」はプロジェクト固有の完成基準を定義しないため、L13の診断対象に含めない。

## 重複検出

- 正規化タイトル
- 別名
- 日付
- 種別
- 親
- 外部URL
- 類似文字列

## 統合

- イベント、タグ、内部リンク、関係、出典、カスタムフィールド、複数親を統合
- 削除側IDへの参照を存続側IDへ変換
- 統合前のプレビューとUndo

## 容量最適化

- 類似度計算結果を恒久保存しない
- 診断結果はオンデマンド生成または短時間キャッシュ
- 大量の重複候補を履歴として保存しない
- 統合Undoだけを10日・所有者あたり50操作・1操作5MiB以内で保持する

## L19統計との共通基盤

- DBから読み出す正規データを `ProjectAnalysisDataset` へ集約し、品質診断と集計を純粋関数へ分離する
- 件数、種別別、タグ別、不足情報、リンク切れ、複数親イベントの集計を同じ分析結果へ含める
- L19ではこのデータセットと集計型を拡張し、診断専用の複製テーブルや長期スナップショットを追加しない
- 1,000項目・10,000イベントでは候補ペアを最大25,000組、表示候補を最大500組へ制限する

## 管理導線

- タイムライン上部の管理操作を「管理メニュー」へ集約する
- 「データを整える」に品質・重複、分類・カスタムフィールド、出典を配置する
- 「表示とプロジェクト」に年代背景、プロジェクト設定・共有、インポート／エクスポートを配置する

## 完了条件

- データ不整合を一覧から修正できる
- 重複アイテムを参照関係ごと統合できる
- 全検証成功
