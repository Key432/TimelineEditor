# タイムライン・編集・詳細

## 12. タイムライン描画

### 12.1 基本構成

- 横軸：時間
- 表示モードは「行表示」「コンパクトレーン表示」「テーブル」を切り替え可能とする
- 既定は従来の「行表示」とする
- 選択中の表示モードは `layout=row|compact|table` としてURLクエリへ反映する
- 行表示では縦軸をタイムラインアイテムとし、左側の項目情報列を固定する
- 行表示ではタイムライン部分のみ横方向へ移動する
- タイムライン領域をドラッグしてパンする
- パン操作中も期間型バーと時点型マーカーを表示し続ける
- 通常スクロールバー、トラックパッドにも対応
- PCでは `Alt + ホイール`、ボタン、スライダー等でズーム
- モバイルではタッチパン、ピンチズーム

### 12.2 ズーム

段階式ズームとし、段階切替には短いアニメーションを付ける。

- カーソル位置を基準にズーム
- ボタン操作時は中央日付を維持
- ズーム後も選択状態を維持
- 「全項目を表示範囲に収める」を提供する
- 表示対象が単一の時点のみでも前後に表示余白を確保し、過大な日単位ズームにしない

### 12.3 時間軸の自動粒度

候補例：

```ts
[
  { unit: "year", step: 500 },
  { unit: "year", step: 200 },
  { unit: "year", step: 100 },
  { unit: "year", step: 50 },
  { unit: "year", step: 20 },
  { unit: "year", step: 10 },
  { unit: "year", step: 5 },
  { unit: "year", step: 2 },
  { unit: "year", step: 1 },
  { unit: "month", step: 6 },
  { unit: "month", step: 3 },
  { unit: "month", step: 1 },
  { unit: "week", step: 1 },
  { unit: "day", step: 1 },
];
```

ルール：

- 主目盛りラベル間は原則80〜120px以上
- 補助目盛り間は原則16〜30px以上
- ラベル衝突時は粗い粒度へ変更
- 余裕ができたら細かい粒度へ変更
- 年／月／日の階層ラベルを表示
- 最小粒度は日

### 12.4 描画方式

- HTMLとSVGを併用
- 巨大な1枚のSVGは作らない
- 行仮想化と表示範囲クリッピングを行う
- タイムライン固有の座標計算、目盛り、クラスタリングは自前実装
- 通常タイムラインはHTMLとSVGを基本とし、Canvas/WebGLの採用は性能測定に基づいて判断する

### 12.5 コンパクトレーン表示

コンパクトレーン表示は、タイムラインアイテムごとの固定行と左側の項目情報列を持たず、時間的に重ならない複数項目を同じ高さのレーンへ配置する高密度な比較表示とする。

#### 表示

- 期間型タイムラインアイテムは従来と同じ横棒、時点型は従来と同じ区別可能なマーカーで描画する
- タイムラインアイテム名は開始位置または時点位置の上に表示する
- 対象種別と開始・終了日は常時表示せず、既存の共通ホバーUIで確認できるようにする
- タイムラインアイテム名、横棒、時点型マーカー、イベントマーカーから既存の詳細表示・編集操作を利用可能とする
- イベントマーカーは関連する各親タイムラインアイテムと同じレーンに描画する
- 固定行と左側の項目情報列がないため、タイムライン領域をつかんだドラッグで左右・上下の両方向へパンできるようにする
- 通常スクロールバーとトラックパッドによる左右・上下移動にも対応する

#### 占有範囲

レーン割り当てに用いる各項目の占有範囲は、次の表示要素をX座標上で合成した最小位置から最大位置までとする。

- 期間型の横棒。`ongoing` はサーバー基準の当日、`unknown` は既定曖昧期間によるフェードアウト終端まで含める
- 時点型のマーカー描画領域
- 親期間の内外を問わず、そのタイムラインアイテムに紐づくすべてのイベントマーカー描画領域
- 開始位置または時点位置の上に表示するタイムラインアイテム名の描画領域
- 前後の固定ピクセル余白 `compactLaneGapPx`。初期値は16pxとし、項目の終端と次項目の開始位置、イベントマーカーと次項目の開始位置が接触しないようにする

イベントマーカーのクラスタリング結果ではなく、クラスタリング前の全イベントマーカー領域を占有範囲へ含める。これにより、ズームによるクラスタ生成・解除でレーンが変化しないようにする。

#### 配置基準と割り当て

- 配置計算には既存のプロジェクト設定 `initial_zoom_preset` から初期表示時に解決した縮尺を使用し、専用の設定項目は追加しない
- `fit-range` の場合は、タイムラインアイテムと期間外を含むイベントのfit対象範囲、および初期表示時の利用可能幅から解決した縮尺を配置基準とする
- 通常のズーム、パン、クラスタリング、画面リサイズではレーンを再計算しない
- タイムラインデータ、イベントデータ、表示対象となるフィルター、グループ化、または初期ズーム設定が変わった場合は再計算する
- 配置対象を開始日時、占有終了日時、安定IDの順に並べ、各項目を占有範囲が衝突しない最上段のレーンへ順番に割り当てる
- 同じレーンの先行項目との間に `compactLaneGapPx` を確保できない場合は次のレーンへ配置する
- レーン割り当ては表示専用の決定的な純粋計算とし、DBへ保存しない
- ズーム変更後も割り当て済みのレーンを維持し、拡大・縮小によって項目の上下位置を変えない

#### 並び順とグループ

- コンパクトレーン表示では並び順の選択と手動D&Dを無効にする
- 行表示で選択していた並び順は保持し、行表示へ戻したときに復元する
- 対象種別によるグループ化は利用可能とする
- グループ化中は対象種別ごとに独立してレーンを計算し、異なるグループの項目を同じレーンへ混在させない
- グループ見出し、対象種別の並び順、展開・折りたたみ、折りたたみ状態は行表示と同じ規則を使用する
- 「非表示にした項目」は既存どおり独立した最下部グループとし、展開された場合はそのグループ内でレーンを計算する

## 13. マーカーとクラスタリング

### 13.1 個別マーカー

- ホバー：タイムラインアイテム／イベントアイテム共通の専用UIでタイトルと日付または期間を表示し、「登録日付」等の固定ラベルは付けない
- クリック：URL連動詳細オーバーレイ
- ダブルクリック：編集フォーム
- イベントアイテムと時点型親アイテムは形状・大きさを変えて区別する
- タイムラインアイテムとイベントアイテムはホバー時に輪郭を強調する
- タイムラインフィールド上でタイムラインアイテムへホバーしたときは、項目名と期間バー／時点マーカーを連動して強調する
- イベントアイテムは親タイムラインアイテムのホバー強調より前面に表示し、重なった位置でイベントアイテムへホバーすると、輪郭強調の対象を親からイベントへ切り替える
- イベント種別の形状にかかわらず白い円形の縁取りを付け、縁取りを含む直径はPhase L9以前の単体イベントマーカーと同じ12pxとし、ホバー・フォーカス時は外周をさらに強調する
- イベント種別が未指定のイベントは円形とし、イベント種別で「丸」を選択した場合と同じ形状・大きさで表示する
- タイムライン上のダブルクリックからイベントを追加する場合、スナップした年月日の粒度を日付精度へ明示的に引き継ぎ、精度プルダウンと年・月・日の入力欄を一致させる

### 13.2 クラスタリング

少しでも表示領域が重なる場合はクラスタ化する。

- 同日
- 近接日付
- 枠線を含むマーカー領域の接触
- 連鎖的に接触するマーカー群も1クラスター
- 上下への積み重ねはしない
- ズーム、画面幅、サイドパネル開閉ごとに再計算
- 拡大して重なりが解消したら自動解除

初期候補：

```ts
collisionDiameterPx = 10;
collisionPaddingPx = 0;
eventMarkerRenderDiameterPx = 12;
eventClusterRenderDiameterPx = 24;
```

初期クラスタ生成後、通常マーカー12px・クラスタマーカー24pxの実描画領域で再判定する。クラスタマーカーが通常マーカーまたは別クラスタマーカーへ接触する場合は再結合し、描画後の重なりを残さない。

### 13.3 クラスターホバー

- 含まれるタイトル一覧を表示
- 日付順
- 件数が多ければ内部スクロール
- ホバー表示は確認用

### 13.4 クラスタークリック

- 選択モーダルを表示
- タイトル・日付一覧
- 行クリックで個別詳細オーバーレイ
- キーボード操作対応
- Esc、背景クリックで閉じる

## 14. 並び順・グループ表示

### 14.1 並び順

```ts
type TimelineSortMode =
  | "manual"
  | "startDate"
  | "endDate"
  | "title"
  | "itemType"
  | "createdAt"
  | "updatedAt";
```

- 手動順を永続化
- 自動並べ替えは表示上のみ
- 自動並べ替え中はD&D無効
- 手動順へ戻すと以前の順序を復元
- 昇順・降順を選択可能
- 開始日・終了日の比較は年だけでなく月日まで含む歴史日付の日序数で行う
- コンパクトレーン表示では自動配置を使用するため、並び順の選択と手動D&Dを無効にする

### 14.2 グループ表示

- タイムライン種別でグループ化
- オン・オフ切替
- グループ見出しに名称、件数、および種別に設定した色のSVGアイコンを表示する
- グループ化中は各行に対象種別名を重複表示しない
- 折りたたみ可能
- 折りたたみ状態を保持
- グループ内手動D&D
- 別グループへ移動した場合は対象種別変更
- `is_visible = false` の項目は、対象種別グループとは別に最下部の「非表示にした項目」へ集約する
- 「非表示にした項目」は初期状態で折りたたみ、対象種別の並び順に影響されない
- 「表示中 n / n 行」の分子は、グループの折りたたみや仮想化の描画範囲にかかわらず、`is_visible = true` のタイムラインアイテム数とする。分母は非表示項目を含む全タイムラインアイテム数とする

## 15. タイムライン種別と色

### 15.1 タイムライン種別

- 登録時に既存種別を単一選択
- 入力文字で候補絞り込み
- 一致しない場合はその場で新規作成可能
- タグ入力と同じチップ・候補UIを使い、候補の「…」から名称、色、アイコンを編集する
- アイコンは文字列としてDBへ保存し、クライアントで対応するSVGを表示して視覚的に選択する
- 入力欄と候補ボックス以外をクリックした場合は候補を閉じ、候補専用の「閉じる」操作は置かない
- 「…」で設定を開いている間も候補一覧を展開し、名称、色、アイコン等の変更は即時保存・反映する
- プロジェクト設定から追加、名称変更、並べ替え、非表示、削除可能
- タイムライン上の管理は「分類・関係」右サイドパネルへ統合し、種別・タグ・カスタムフィールド・意味的関係の変更を登録フォームと表示へ即時反映する
- タイムライン種別の色・アイコンおよびイベント種別の色・マーカー形状を変更した場合、項目一覧・イベント一覧のクライアントキャッシュも更新し、ページ再読込なしでタイムラインフィールドへ反映する
- 対象種別による項目の並び替えは名称ではなく `timeline_item_types.sort_order` を基準にする
- 使用中種別の削除時は別種別への移行を要求

### 15.2 色

- 対象種別に既定色
- 個々のタイムラインアイテムで上書き可能
- 上書き解除時は種別の現在色へ戻る
- 横棒、曖昧グラデーション、イベントアイテムマーカーは継承色を使用
- 選択・ホバー・検索一致は色変更ではなく輪郭等で表す

## 16. 登録・編集UI

### 16.1 サイドパネル

右サイドパネルは十分な幅と余白を持たせ、プロパティ領域と本文領域を視覚的に分ける。画面幅に応じて幅と内部グリッドを切り替え、狭い画面で入力欄が横にはみ出さないようにする。フォームは通常幅、ワイド、最大化を切り替えられる。

登録・編集：

- 名称
- タイムライン種別
- 時間形式
- 開始日／時点日
- 終了状態
- 曖昧フラグ
- 個別色
- 本文、出典、外部URLは枠で囲わず、区切り線を用いてパネルへ直接入力するように表示
- イベントアイテム一覧
- 表示・非表示
- 分類・関係管理パネルを開くボタン

「分類・関係」パネルは開いた時点で入力欄を自動フォーカスせず、「タイムライン種別」「イベント種別」「タグの統合」「カスタムフィールド」「意味的関係」の順で表示する。

配置・入力部品：

- 時間形式は「期間」「時点」を比較しやすいセグメント化された選択ボタンとして表示し、キーボード操作と選択状態の読み上げに対応する
- 「おおよそ」「対象種別の色を上書き」「タイムラインに表示」等の真偽値は、ラベル、短い補足、操作部品を同じ設定行へまとめ、色だけに依存せず状態を示す。「おおよそ」はタイムライン／イベントの各フォームで同じ枠付きチェックボックスを使い、対応する年月日の右側へ配置し、狭い画面では日付グループの下へ折り返す
- 時代選択は利用者向けに「紀元後」「紀元前」と表示する。原資料上の日付表記は「日付表記の手動入力（任意・例：平成10年）」として日付入力行の下へ全幅で表示する
- 「おおよそ」が有効な日付は、タイムライン、詳細、検索で日付の後ろに「頃」を付けて表示する
- 開始日、終了日、時点日は年・月・日を一つの日付グループとして扱う。年入力は想定桁数に必要な幅へ抑え、広いパネルでは関連する日付グループを横並び、狭いパネルではグループ単位で縦積みにする
- 月・日入力は年入力より狭くし、ラベルとエラー表示を含めてもレイアウトがずれないCSS Gridを使用する
- 「対象種別の色を上書き」を有効にすると、カラーピッカー、現在色のプレビュー、検証可能な16進カラー値、上書き解除を同じ領域に表示する
- カラーピッカーだけに依存せず、キーボード利用者が16進カラー値を入力できるようにする
- 別名とその入力欄は任意項目として既定で折りたたみ、設定済み件数を折りたたみ見出しに表示する
- 本文、出典、外部URLはプロパティ群と区切り、保存操作は長いフォームでも見失わない位置に置く

タイムラインアイテムの新規作成時は、同じサイドパネル内で0件以上のイベントアイテムを追加、編集、削除できる。イベント編集UIの項目順、日付入力、エラー表示は共通詳細シェルのイベント管理UIと共通化する。時間形式が時点型の間はイベント追加UIを無効化し、理由を表示する。保存時は親とイベントを単一リクエストで送信し、親を先に作成してから各イベントを個別に保存する。イベントの一部または全部が失敗しても親の作成成功は維持し、失敗したイベントのタイトルを通知する。

タイムラインアイテムとイベントアイテムの新規作成パネルでは、作成対象を始点とする関係を0件以上追加できる。親項目またはイベント本体を作成した後に関係を保存し、一部の関係保存に失敗しても本体の作成成功は維持して失敗した関係種別を通知する。

### 16.2 詳細編集ページ

- タイムライン上の編集では別ページへ遷移せず、右サイドパネル内ですべての入力項目を表示する
- 直接URLから開く編集ページでも同じ入力構造を使用する
- 長文説明
- イベントアイテム管理
- 出典
- 外部URL
- 管理情報
- カスタムフィールド

### 16.3 保存

- 入力停止後のデバウンス自動保存
- フォーカス移動時の即時保存
- 未送信変更がある状態で閉じる場合は確認
- 保存中は重複送信を防止
- 保存中の追加変更は次の保存キューへ送り、更新バージョンで競合を検出
- 保存済み、保存中、未保存、失敗、オフライン、再試行中を表示
- 未送信下書きをIndexedDBへ保存し、DB保存成功後に削除
- 保存成功後にTanStack Queryキャッシュを無効化
- 保存したタイムラインアイテム／イベントアイテムの詳細キャッシュを新しい値へ更新し、編集画面を閉じた後の詳細表示へ反映
- 保存後にページ遷移せず再編集した場合も、詳細キャッシュの最新値をフォームへ反映する
- タイムラインへ即時反映

## 17. 詳細ページ

### 17.1 タイムラインアイテム

表示：

- タイトル
- 対象種別
- 期間または時点
- 曖昧表記
- 終了状態
- 本文
- 出典
- 外部URL
- イベントアイテム一覧。既定は件数だけをコンパクトに表示し、展開すると各イベントのタイトル、日付、詳細ページへのリンクを表示する
- 編集ボタン（所有者のみ）
- タイトルまたはタイムライン上の横棒／時点マーカーをクリックして開く

### 17.2 イベントアイテム

表示：

- タイトル
- 日付
- 曖昧表記
- 親タイムラインアイテム
- 本文
- 出典
- 外部URL
- 編集ボタン（所有者のみ）

両詳細表示は大きなタイトルを最上部へ配置し、プロパティ領域、区切り線、見出しを付けない本文領域の順に表示する。URL連動オーバーレイでも説明用の固定見出しは表示しない。

URL連動オーバーレイでは、詳細オプション、全画面化、閉じるアイコンを右上の同じ行へ固定し、本文上部に専用の操作行や余分な余白を設けない。通常、ワイド、最大化の表示幅を閲覧・編集の両モードで選択できる。オーバーレイでは表示幅に合わせてモーダル外枠と詳細本文を滑らかに拡縮し、通常ページでは詳細本文自体を同じ3段階で拡縮する。表示幅のユーザー向け文言は「通常」「ワイド」「最大化」とする。通常の個別ページでは左右の余白、書体、編集モードの操作を単一の「詳細オプション」アイコンへまとめ、パンくずリストと同じ行へ配置する。

所有者用詳細ページは本文末尾の操作領域に主要な「編集」ボタンを表示する。「詳細オプション」内にも「編集」を残し、「変更履歴」と「ゴミ箱へ移動」は本文末尾から「詳細オプション」内へ移動する。通常ページとURL連動オーバーレイで同じ操作配置を使用する。

詳細表示にはゴシック体／明朝体の書体切り替えを設ける。

- タイムラインアイテムとイベントアイテムのタイトル、本文、出典へ同じ書体を適用する
- 所有者用の通常詳細ページ、URL連動オーバーレイ、公開詳細ページで利用できる
- 表示幅と書体は詳細ページごとにブラウザのlocalStorageへ保存し、同じ詳細を再表示した場合に復元する
- 別のタイムラインアイテム、イベントアイテム、公開詳細ページへ設定を共有しない
- プロジェクトデータやSupabaseには保存しない
- 日本語のシステムフォントスタックを使用し、外部Webフォントやフォントファイルを保存しない
- 切り替え操作はキーボードと読み上げに対応し、選択状態を色だけで伝えない

イベントアイテムの通常ページでは、「タイムラインアイテム > イベントアイテム」の順にパンくずを表示する。親が1件ならその親へ直接リンクし、複数なら手動 `sort_order` 順の折りたたみメニューから任意の親を選んで遷移できる。親の解決処理は詳細ページシェルの外で行う。

### 17.3 本文

- Markdown原文だけを保存し、レンダリング済みHTMLは保存しない
- 見出し、強調、打ち消し線、コード、リスト、引用、水平線、表、外部リンク、コールアウトを扱う
- 編集／プレビューを切り替え、編集内容をプレビューへ反映する。分割表示は設けない
- 本文の編集欄とプレビュー欄は出典・参考文献欄と同じボーダーなしの透明背景、内側余白、本文文字サイズを使用する
- `/help` に静的生成するヘルプ一覧、`/help/markdown` に静的生成するMarkdown記法ヘルプを設け、本文編集欄から別タブで参照できるようにする。他のヘルプは今後追加する
- Markdown記法ヘルプにはプロジェクト内リンクの入力候補、安定ID、名称変更時の維持、リンク切れ表示を記載する
- raw HTML、画像、ファイル、iframe、video、audio、SVG埋め込み、JavaScript URL、data URLは扱わない
- AST変換後に許可要素だけを描画する

### 17.4 出典・参考文献

- 従来の自由記述による出典・参考文献を引き続き利用できる
- 編集フォームは自由記述を既定タブとし、任意の詳細登録タブへ切り替えられる。両方式は同時に保存・表示できる
- 資料名、著者、出版社、刊行年、ISBN、URL、参照日、引用キー、注記を持つ資料マスタをプロジェクト単位で管理する
- タイムライン上部の「出典・参考文献」は、「分類・関係」と同じ幅の右サイドパネルを開き、資料の一覧確認・追加・編集と出典未設定項目の確認を提供する
- `/projects` の各プロジェクトタイルでは「設定を開く」の左に「出典・参考文献」を置き、`/projects/[projectId]/sources` へ遷移する
- サイドパネルと `/projects/[projectId]/sources` は共通の資料管理UIを使用し、「資料マスタ」「新しい資料」「出典未設定の項目」の順で表示する。資料一覧は資料名と著者だけを既定表示して編集欄を折り畳む
- タイムラインアイテム・イベントアイテムと多対多で関連付け、ページ番号、章、引用箇所等の個別ロケータを持つ
- アイテム・イベントの詳細では資料名、著者、刊行年を折り畳み見出しに表示し、書誌情報と個別ロケータを展開して確認できる
- 同一資料を複数項目から再利用し、書誌情報を本文へ重複保存しない
- Markdown本文中の引用記法、BibTeX、CSL JSONの入出力を扱える構造とする
- Markdown本文中の引用記法は `[@引用キー]` とし、当該項目へ関連付けた資料へ解決する
- 詳細モーダル内の引用キーと資料マスタリンクは、モーダルを残さず資料マスタへページ遷移する
- 外部ページ本文や書影は保存しない

### 17.5 意味的関係

- アイテム／イベントの詳細表示では、関係種別、始点、向き、終点を閲覧専用の一覧にし、始点と終点を各詳細ページへのリンクにする。「編集」を押した編集モードと「分類・関係」パネルから関係の追加・編集・削除を行う。
- 種別は「影響」「参照」「協働」「師弟」「対立」「継承」「その他」を候補表示し、候補外の日本語名称も自由入力できる。
- 線は単線／二重線、始点矢印／終点矢印を切り替えられる。矢印を持たない関係は方向なしとして扱う。
- 線は始点から垂直、タイムラインバーとずれた高さを水平、終点へ垂直の順に接続し、最後の線分を時間軸と水平にしない。タイムラインの項目より前面、時間軸ヘッダー、行表示の情報列・編集列、グループ見出し、詳細オーバーレイより背面に描画する。
- 種別グループをまたぐ線は、折りたたみ時も各グループ見出しの下を通り、折りたたまれた側の見出し下端へ接続する。
- ツールバーで「標準」「すべて表示」「すべて非表示」を切り替える。「標準」は表示範囲内の線を半透明灰色にし、ホバーまたはフォーカス時に着色する。「すべて表示」は表示範囲内の線を常時着色する。いずれも少なくとも一方の端点が表示年代内にある関係へ限定する。
- 線はホバー、クリック、Enter／Spaceで関係種別・両端・注記を確認できる。
